在有限的时间内，创造更大的价值。

## 工作原则

1. **管理结果**：明确要解决的问题和完成标准，不要用工时、代码量或任务数衡量价值
1. **滚动规划**：目标拆成可验证的 milestone，再拆成任务；只详细规划最近一两周
1. **优先验证风险**：先解决关键未知。探索任务明确问题、投入预算和停止条件。
1. **任务可执行**：普通任务尽量在几小时到一两天内完成；复杂工作拆分，未知问题先实验。
1. **限制并行**：每人一个主要任务，等待时可推进一个辅助任务；优先解除阻塞。
1. **依据证据调整**：完成后留下结果与结论；科研负结果同样有价值，证据不足时不强下结论。

## GitHub Projects

一个 Project、一个 Board、三个状态：`Todo → In Progress → Done`。

| 内容                       | 放在哪里                       |
| -------------------------- | ------------------------------ |
| 目标、当前里程碑及验收条件 | Project README                 |
| 任务、完成条件、负责人     | Issue 正文与 Assignees         |
| 执行状态                   | Projects 看板                  |
| 阻塞、结果、重要决定       | Issue 评论；详细记录用链接关联 |

每个 Issue 只需写清：

```markdown
目标：要得到什么结果？
完成条件：如何验证？
约束（按需）：依赖、风险、投入预算。
```

每周从 `Todo` 中挑出最重要的一到三项，放到前面；开始执行时移入 `In Progress`，验证完成、补充证据后关闭 Issue 并确认状态为 `Done`。取消任务注明原因。

先用卡片排序表达优先级。阶段任务较多时再使用仓库 Milestone；需要交接时再加 `Review`。配置随实际需要增加，任务状态只维护这一份。

## 每周回顾：OODA

1. **观察（Observe）**：有哪些结果、阻塞和新信息？
1. **理解（Orient）**：目标和假设还成立吗？最大风险是什么？
1. **决策（Decide）**：继续、调整或停止什么？下一步最重要的是什么？
1. **行动（Act）**：更新任务、负责人和范围，开始执行。

关键结果和阻塞及时异步更新，需要共同判断时再讨论。里程碑结束时验收成果；定期清理失去价值的待办，复盘只改一两项具体问题。

只保留帮助决策与协作的记录，避免重复维护任务清单、日报和周报。
