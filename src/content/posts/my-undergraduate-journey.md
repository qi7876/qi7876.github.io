4 号，出去爬山了

5 号，CS61B 同步进度了，今天还尝试了使用 Jujustu colocated with Git，真的太好用了，比 Git 的 mental model 要简单很多（Git 的 stash 机制很反人类，staging area / index 也同样有些多余，jj 直接让 commit 作为 workspace，消除了这些复杂度），概念上也消除了 Git 瞎起名带来的误解（比如 branch，实际上只是个 reference，Git 使用 branch 让人很容易误解成是从 main 分叉出的一整条 commit 链，而在 jj 中，作者使用 bookmark 来指代）

6 号，推进 CSAPP 105 / 1076，明天准备继续推进科研了

7，8 号，推进了一些科研

9 号，搞了一天软件工程实验课。写 rust 真是痛苦又快乐，果然什么都有 trade-off，rust 太严谨导致写程序的人很痛苦，怪不的很多人说 Go 语言更适合工程，因为写起来确实简单，complexity 控制的很好

10 号，继续软工，又把 jj 换回 git 了，git 用的太多所以习惯已经缓不过来了，并且模型训练语料中 git 更多，所以考虑到 agent 也得用着顺手，我还是切换回 git 了，是的，我现在选择工具已经把 agent 能不能用的起来也纳为一个重要因素了

11 号，依旧软工，今天应该差不多能把基础的一版做完，然后后面要多花时间在科研上了，再做一篇工作之后准备和老师说后面暂时停一下，把毕设做了，以及完成自己的规划

关于 AI 时代计算机教育的意义：https://htmx.org/essays/yes-and/。
感觉这不仅适用于计算机教育，所有学科都应该如此，本科生应该让自己平稳度过 junior 阶段，找到感兴趣的方向，打下坚实的知识基础，对自己的领域有系统性的认识，这样后面才能以 senior 的身份稳步前进。
跳过 junior 阶段想直接驾驭 agent 很容易造出一个自己不理解且无法掌控的系统。
如果只是面向成果，有一个可交付的内容（比如组会赶 DDL 必须得有东西讲给老师听，不然显得这周没干活，我以前就这样），这样没啥问题，但是长期来看这并不利于自身的发展，有可交付的内容不等于在往好的方向走（水论文 vs 确实解决了真正亟待解决的问题，刷实习 vs 确实学到了真技术/经验）。

14 号，终于结束软工了，目前把基本功能都解决了，并且持久化、Robust 这些做的比较好，项目代码架构也重新组织了，挺清晰，后面就趁上课的时候完善一下然后加入一些高级的功能，比如 WebUI、定时任务这些，然后就不再单独抽时间做这个了。
整体主打的大概是极致的稳定、抗风险，尽量减少损坏，真损坏了减少影响。

btw，上周的 CS61B 还没做，先放一下和这周的一块清掉吧

15, 16 号，推进科研

17 号，组会时间，然后开始清理 cs61b，攒了两周了

下午调整了一下设置，把之前用的不顺心的全改了，主要是 kitty 和 starship，还有 tmux 没配完，今晚清理一下

18 号，大幅更新了工具链，kitty -> ghostty，tmux -> zmx，zsh -> fish

换 terminal emulator 主要是战未来，我很看好 ghostty。后两者就是纯升级了，tmux 这么基础的软件居然在 3.8 更新后改变了我配置的行为，难以置信，加上我一直都认为自己不需要这么重的 terminal multiplexer，所以换成了 zmx，一个基于 libghostty 的轻量 session persistent 工具，然后用 starship 检测一下 zmx session 给个标记就行；zsh 到 fish 就是纯升级了，各方面体验都是碾压的；至于兼容性，写脚本时都是用 sh，所以一般没啥问题，真有问题让 Agent 做点 Patch 就行了

然后推进了一点 CS61B，今天状态不是很好，头昏昏的
